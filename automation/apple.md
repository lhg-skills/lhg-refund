# Apple App Store（半自动）

> 收款方是 Apple，平台客服无权退。**这是唯一入口，别在 App 里找。**
> 流程短，但有两处必须用户亲手做：Apple ID 登录（双重认证）、最终提交。

## 先确认三件事

1. **这笔钱是不是 Apple 收的？** 看收据邮件（Receipt）或支付账单是否显示 Apple。
   不是 → 立刻停，回平台走正常退款，别在这里浪费时间。
2. **买的是什么？** 订阅 / App 内购 / 一次性购买。
3. **有没有"未交付"或"未提供访问权限"的事实？** 这是通过率最高的角度。

## 执行步骤

### 0. 打开入口

```js
const task = await taskSpace("apple refund");
const page = task.page("p1");
await page.goto("https://reportaproblem.apple.com/");
console.log({ spaceId: task.spaceId, page: page.label });
console.log(await page.snapshot());
```

> 这里允许直达：reportaproblem 本身就是入口页，不存在"深链暴露"问题。
>
> **入口核验（2026-11-02 实测）**：未登录时直接访问会 302 跳转到 `idmsa.apple.com` 的 Apple ID 登录页——**不登录根本到不了退款流程**，这正是下一步必须 `handOff` 的原因。

### 1. 登录（必须交还用户）

Apple ID 登录会触发双重认证——验证码发到用户自己的设备上，agent 拿不到，也不该拿。

```js
await task.handOff();
```

告诉用户：

> 请在浏览器里用你的 Apple ID 登录（会要求输入手机收到的验证码），登录完成后跟我说一声。

用户确认后：

```js
const spaceId = 12; // 换成上一轮打印的 spaceId
const task = await takeOverTaskSpace(spaceId);
const page = task.userPage();
console.log(await page.snapshot());
```

**不要试图做全自动**：双重认证绕不过去，硬试只会触发风控。

### 2. 走流程（按 Apple 官方描述的四个动作）

```
点「我需要」→ 选「请求退款」→ 选取退款原因 → 选 App、订阅或其他项目 → 提交
```

每步之间停 500–1200ms，用 snapshot 确认再往下点。

### 3. 找项目（关键判断点）

在项目列表里找用户要退的那一笔。

| 情况 | 说明 |
|---|---|
| 找到了 | 继续，勾选 |
| **找不到** | 说明这笔不是 Apple 收的钱 → **停止**，回平台走正常退款 |
| 有多笔同名 | 按金额和日期让用户确认是哪一笔，不要猜 |

### 4. 选原因（这一步决定成败）

Apple 会给几个原因选项。**必须按真实情况选，不许为了过审编造。**

| 真实情况 | 对应方向 | 通过率 |
|---|---|---|
| 孩子误点 / 账号被盗 / 不知情 | 未经授权的购买 | 高 |
| 付了钱但功能打不开、内容加载不出 | 未收到项目 / 项目无法使用 | 中高 |
| 订阅取消了还被扣下期 | 未提供访问权限的周期 | 中高 |
| 就是不想用了 / 不符合预期 | 不符合预期 | 低 |

**跟用户说清楚**：编原因一旦被判定滥用，会留下记录，之后所有退款都会被拒，还可能影响 Apple ID。这个代价远大于一次退款。

### 5. 写说明（可选但建议）

如果页面有描述框，用这段：

```
该笔购买后未能正常使用：{具体现象}。
已尝试 {做了什么}，问题仍存在。
申请退还 {金额} 元至原支付方式。
```

中文长文本用 `keyboard.insertText` 分段上屏，每段 20–40 字，段间停 300–800ms。

### 6. 停，交给用户提交

```js
// 走到最后一步，停下
// 告诉用户：核对项目和金额，确认无误后自己点提交
```

**agent 不点最终提交。** 这是 Apple 账号，误操作影响面比平台账号大得多。

### 7. 记录

- 提交后的页面状态 / 请求编号
- 提交时间
- 告知用户：官方写明 **24–48 小时**给最新信息，结果发到邮箱

### 8. 收尾 + 一个必做提醒

```js
await task.finish({ keep: [] });
```

**退款 ≠ 取消订阅。** 必须单独做一步：

```
设置 → Apple ID → 订阅 → 选中该订阅 → 取消订阅
```

不做这一步，下期照扣。这是最高频的"我明明退了还被扣"。

## 被拒之后

Apple 拒绝后，中国用户仍可向 12315 投诉（对象是 Apple 的中国主体），但成功率不高——它的条款给了很大裁量空间。

金额小的，接受结果；金额大的，走 `templates/complaint-12315.md`，重点写"未提供所购服务"而不是"我要退款"。

## 待验证项

- 原因选项的当前措辞与数量
- 提交后是否给请求编号（历史上有时只有邮件确认）
