# WPS（半自动）

> WPS 有一个别家没有的东西：**明文的「买错会员」通道**。
> 这说明它内部承认误购可退，只是不公开标准。所以核心不是"点得对不对"，是"**怎么把反悔说成买错**"。

## 先判断：是"买错"还是"反悔"

| 事实 | 定性 | 过审概率 |
|---|---|---|
| 想买超级会员，买成大会员（或反过来） | 误购 | 高 |
| 想买 1 个月，买成连续包年 | 误购 | 高 |
| 已经是会员，又买了一次 | 重复购买 | 高 |
| 给错账号充值 | 误购 | 高 |
| 买对了，就是不想用了 | 反悔 | 低 |

**如果用户其实是"反悔"，不要硬编"买错"。** 一旦被拆穿（后台能看到购买路径和页面停留），后面连正常协商的机会都没了。

反悔的情况走另一条线：`templates/auto-renewal.md`（如果是自动续费）或主张"未使用"。

## 入口

| 通道 | 说明 |
|---|---|
| WPS 客户服务中心小程序 → 「买错会员」 | 官方 FAQ 明确写的通道，首选 |
| `helpdesk.wps.cn` | 网页端帮助中心，可提交工单 |
| App 内客服 | 兜底 |

> 三个入口的当前形态**待真机验证**。首次执行后把实际路径回写到本节。
>
> **入口核验（2026-11-02 实测）**：`helpdesk.wps.cn` 返回 200，页面标题「WPS 服务中心」，是 JS 渲染的单页应用——所以必须等渲染完成再 `snapshot()`，不要 `goto` 后立刻找元素。

## 执行步骤

### 0. 打开入口

```js
const task = await taskSpace("wps refund");
const page = task.page("p1");
await page.goto("https://helpdesk.wps.cn/");
console.log({ spaceId: task.spaceId, page: page.label });
console.log(await page.snapshot());
```

### 1. 判断登录态

网页工单通常要登录 WPS 账号。需要登录 → `await task.handOff()`，让用户自己登。

### 2. 找「买错会员」入口

在帮助中心/客服中心里找"买错""误购""退款"相关入口。

- 找到 → 进表单
- 找不到 → 退到在线客服，直接用下面的话术

### 3. 填表（agent 填，用户提交）

表单通常要：订单号、购买时间、金额、买错的说明。

**说明字段的写法（决定过审）：**

```
误购说明：
我于 {YYYY-MM-DD} 购买 {实际买到的套餐}，本意是购买 {想买的套餐}。
订单号 {X}，金额 {Y} 元。
购买后未使用会员权益，申请退款并改购正确套餐。
```

**关键**：一定要写"本意是买 X"，只说"买错了"没有信息量，审核看不出你是真错还是反悔。

### 4. 停在提交前

填完让用户核对：**订单号、金额、说明里的套餐名**。确认后由用户点提交。

### 5. 记录

工单号 / 受理编号 / 提交时间 / 页面上写的处理时限。

## 话术（三条，按顺序用）

**① 首轮（走"买错"通道时）**

```
我于 {日期} 购买 {套餐}，实为误购：本意购买 {目标套餐}，误选为 {实际套餐}。
订单号 {X}，金额 {Y}，尚未使用会员权益。
请按「买错会员」通道处理退款，原路退回。
```

**② 通道被拒（转"未使用"角度）**

```
该笔订单的会员权益我一次都没有使用（可核验后台使用记录）。
服务未实际发生，请按未消费部分退款，并告知计算方式。
```

**③ 如果是自动续费扣的**

```
这笔 {日期} 的 {金额} 元是自动续费扣款，扣款前我没有收到显著提醒。
请提供扣费前的提醒记录；如无法提供，请退款并关闭自动续费。
```

## 被拒之后

按 `references/channels.md` 的顺序：客服工单 → 48h 无果 → 支付渠道投诉 → 12315。

投诉对象填 **WPS 的运营主体全称**（看支付账单收款方，不是"金山办公"想当然）。
