# 拟人化执行规范（ego-lite 版）

> 解决"跑着跑着被识别成 AI"。核心不是"伪装"，是**别做人类不会做的事**。
> 本规范只用于用户本人账号、本人退费，不涉及他人账号、不批量、不代退。

## 一、先搞清楚：之前为什么会被识别

上一版走的是 `agent-browser`（Playwright/无头 Chromium）全自动路径。它的机器特征不是一处，是一串：

| 特征 | 站点看到的样子 |
|---|---|
| `navigator.webdriver = true` | 脚本控制的浏览器，最直接的标记 |
| 无头模式 / 默认 UA | 无 GPU、无插件、窗口尺寸异常 |
| `page.fill()` 直接赋值 | 输入框瞬间填满，无按键事件 |
| 点击坐标瞬间跳跃 | 鼠标从 A 瞬移到 B，无轨迹 |
| 固定 `sleep(2000)` | 每一步间隔完全一致 |
| 直达深链 `.../subscription/manage` | 从不经过首页，直接进四层页面 |
| 一次性提交长文本 | 一段话 0 毫秒粘贴进对话框 |
| 新设备 + 新 IP + 新指纹 | 账号环境和历史登录对不上 |

其中**杀伤力最大的两条**是「直达深链」和「输入无按键事件」——这两条几乎不可能是真人。

## 二、ego-lite 给了什么

| 能力 | 对应解决 |
|---|---|
| 真实 Chromium（非无头） | UA、GPU、插件、窗口全部正常 |
| 持久 TaskSpace + 用户自己的 profile | 复用用户**已登录的 cookie 和设备指纹**，账号环境一致 |
| `task.handOff()` / `takeOverTaskSpace()` | **登录环节交还给用户亲手做**，agent 全程不碰密码、不碰验证码 |
| `page.mouse.move/click/wheel` | 真实指针事件，有轨迹、有滚动 |
| `page.keyboard.type()` | 逐字产生 keydown/keypress/input 事件 |
| Page 会话隐藏 CDP console 消息 | 官方 usage guide 原话："sites cannot detect the automation" |

最后一条能挡掉"控制台被探测"，但**不是免死金牌**。真正决定成败的是下面这些行为规范。

## 三、铁律（不可协商）

1. **登录永远交还用户。**
   走到二维码页或短信验证码页，`await task.handOff()`，结束本轮，告诉用户"请在浏览器里完成登录，完成后告诉我"。
   用户确认后 `takeOverTaskSpace(spaceId)` 恢复，接着做。**agent 不输密码、不读短信、不猜手机号。**

2. **最终提交永远等用户亲口确认。**
   走到"确认退款"弹窗前停下，把金额、去向、后果复述清楚，等用户明确说"确认"，才点。

3. **不并发、不批量、不循环重试。**
   同一账号 1 小时内最多 1 次退款流程。失败 2 次就停，报告原因，不要"再试一次"。

## 四、行为规范（照做，别自由发挥）

### 4.1 进入路径

- ❌ 不要一上来 `goto("https://xxx.com/subscription/manage")`。
- ✅ 从**首页**进入：`goto("https://xxx.com/")` → 停顿 → 快照 → 找"我的/头像" → 逐级点进去。
- 理由：真人退款是从 App 里一层层找的，直达四层页面是脚本的典型特征。

### 4.2 输入

| 场景 | 做法 |
|---|---|
| 短字段（手机号、验证码以外的信息） | `keyboard.type(text, { delay: 60~140 })`，逐字 |
| 长文本（投诉描述、工单正文） | 分段 `type`，每段 20~40 字，段间停顿；**不要**一次 `paste` 上千字 |
| 禁止 | `page.fill()` 直接赋值、`evaluate` 改 value、`insertText` 整段灌入 |

### 4.3 指针与滚动

```
先把鼠标移到目标附近（mouse.move，两三个中间点）→ hover 100~300ms → click
滚动用 mouse.wheel(0, 300~600)，一次不要滚一屏以上
```

- 点击前目标必须在视口内（ego 会自动滚，但**自动滚也要留时间**）。
- 不要连点：两次点击之间至少 250ms。

### 4.4 节奏

| 动作 | 建议间隔 |
|---|---|
| 两个连续点击 | 250~800ms（随机） |
| 点击后等页面 | 先 `waitForSelector` / `waitForURL`，再额外停 300~900ms |
| 读页面（看条款、看金额） | 1.5~4s，别 200ms 扫完就点下一步 |
| 翻页/切换 tab | 800~1500ms |

**所有延时都要随机化**，不要 `waitForTimeout(2000)` 一路到底——恒定间隔本身就是指纹。

### 4.5 会话长度

- 单次流程控制在 **15 分钟**内。
- 超过 20 分钟没有任何用户输入 → 主动收尾，结束 TaskSpace，别挂着。

### 4.6 屏幕与观察方式

- 优先 `snapshot()`（语义），需要看视觉才 `screenshot()`。
- 不要为了"看起来像人"去无意义地狂截图——截图不影响站点，只烧你的 token。

## 五、禁止清单

| 禁止 | 原因 |
|---|---|
| 无头模式、改 UA、装 stealth 插件 | ego-lite 本身就是真浏览器，改反而制造异常 |
| `page.evaluate()` 直接 `form.submit()` / 改 DOM | 不产生真实事件，等于自曝 |
| `page.cdp("egoAutomated.disable")` 去关保护 | 关掉后站点反而能探测到 CDP |
| 用同一 profile 同时开多个 TaskSpace 跑不同账号 | 指纹串号 |
| 在对话里一次性粘贴整篇投诉长文 | 人类是分段打的 |
| 页面报错后连续重试 3 次以上 | 高频重试是最明显的机器特征 |

## 六、上线前自检（每次跑之前过一遍）

- [ ] 用的是用户自己的 profile，不是新建空白环境？
- [ ] 登录是 `handOff` 交还用户完成的？
- [ ] 进入路径是从首页点进去的，不是直达深链？
- [ ] 输入是逐字 `type`，不是 `fill`？
- [ ] 延时是随机的，不是固定值？
- [ ] 最终提交按钮，是在用户明确说"确认"之后才点的？
- [ ] 本次会话没有并发第二个账号？

七条全过，再跑。任何一条没过，先改，别赌。

## 七、如果还是被拦

被拦之后**不要换招硬闯**（换 IP、换号、加插件），那会把"疑似"变成"确认"。

正确动作：
1. 停下来，截图当前页面（这是证据）；
2. 判定是"风控拦截"还是"页面改版"——前者出现验证码/滑块/人机校验，后者是入口不见了；
3. 风控拦截 → 改用**人工路径**（`channels.md` 里的渠道顺序 + `templates/` 里的话术），别在自动化上耗；
4. 页面改版 → 记录新路径，走 skill 的质检上报流程。

一句话：**自动化是加速器，不是唯一路径。被拦了就换人工，别跟风控对赌。**
