# 平台卡 Schema

每张平台卡固定字段。新增平台照这个填，不许自创字段——字段一乱，路由和检索就废了。

```yaml
platform: 扣子 Coze            # 展示名
site: coze.cn                  # 主域名
category: AI工具               # AI工具/内容社区/在线教育/长视频/音乐/网盘/办公/电商/本地生活
pricing:                       # 该平台存在的付费形态，可多选
  - 连续包年
  - 连续包月
  - 积分包
refund_policy: 有条件          # 支持 / 有条件 / 不支持 / 未公开
entry:
  web: https://...             # 网页端入口（URL + 点击路径）
  app: "我的 → ..."            # App 内路径；没有就写 null
  cs: "在线客服入口"            # 人工客服怎么找
  hidden: "入口藏在支付记录的操作列"   # 为什么用户自己找不到（没有就 null）
ratio_refund: unknown          # yes / no / unknown —— 是否支持未使用按比例退
timeline: 2-3个工作日           # 官方承诺到账时效
rejection_lines:               # 客服常用拒绝话术，原文风格
  - "已开通不支持退款"
proof_points:                  # 用户必须提前固定的证据
  - 订单页（含订单号）
  - 支付账单收款方
ios_rule: "iOS 内购必须走 Apple 退款"   # 有商店代收时必填，否则 null
notes: ""                      # 特殊规则
status: 实测                   # 实测 / 公开资料 / 待验证
last_verified: 2026-11-02
sources:                       # 每条事实的来源，至少 1 条
  - https://...
```

## 字段规则

1. **`refund_policy` 只填四选一**，不要写"视情况而定"——视情况的部分写进 `notes`。
2. **`ratio_refund` 必须三选一**。没查到就写 `unknown`，不要猜。
3. **`rejection_lines` 要原文风格**（客服真会这么说的话），不要润色成书面语。
4. **`sources` 不能空**。没有来源的事实不许写进卡片。
5. **`status`**：
   - `实测` = 我们自己或用户成功走通过，有截图/结果；
   - `公开资料` = 官方文档/帮助中心写明，但没实测；
   - `待验证` = 只有用户口述或社区帖子，未交叉验证。
6. **`last_verified`** 每次改动都更新。超过 6 个月的卡片要降级为 `待验证`。

## 平台卡与主流程的关系

- 主流程（`decision.md`）决定**走哪条路、说什么**；
- 平台卡只提供**入口在哪、条款怎么说、客服叫什么、证据要什么**。

平台卡里不要写话术（话术在 `scripts.md` 通用、`platform-scripts.md` 按平台），也不要写法规（法规在 `legal.md`）。三者分开，改一个不用动另外两个。
