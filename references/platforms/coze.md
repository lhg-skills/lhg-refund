## 为什么用户自己找不到

四层嵌套 + 术语错位：

```
订阅管理 → 套餐管理页 → 顶部页签「套餐订阅」
→ 下滑到「支付记录」表格 → 找目标订单行
→ 最右侧「操作」列 → 「申请退款」
```

四个原因，按杀伤力排序：

1. **藏得深**：不在会员中心首页，在"支付记录"的操作列——没人会去支付记录里找退订。
2. **叫法错位**：用户找「退订/取消会员」，页面叫「申请退款」。关键词对不上＝隐身。
3. **自动续费已关时没有"取消"按钮**：没什么可取消的（到期自动失效），页面不会给你退订按钮，唯一出路是退款。
4. **手机端可能没有**：桌面网页端走通，App 内导航结构不同，未实测。

## 决策树（先决策，再动手）

```
自动续费已关闭？
├─ 是 → 到期不再扣费。二选一：
│   ├─ A 什么都不做：权益保留到到期日，零风险
│   └─ B 申请退款：拿回剩余价值，但立即失去全部剩余权益、不可撤销
└─ 否 → 先关「自动续费」（停止未来扣款），再按上面 A/B 选
```

**必须把 A/B 的利弊讲清楚，等用户拍板。** 用户不说"确认退款"，不进下一步。

## 执行要点

1. 登录态检查：打开 `https://www.coze.cn/`，看右上角是否显示头像/昵称。
2. 登录：优先「抖音扫码登录」，二维码展示给用户，**停下等用户确认扫完**；备选手机号+短信，验证码由用户亲口提供，agent 不读短信。最多 3 次，失败即停。
3. 核对确认弹窗五项：退款商品 / 订单编号 / 支付方式 / 预计退款金额 / 条款原文。
4. 复述"点下去立即失去会员、不可撤销"，拿到明确确认后再点「确认退款」。
5. 四项核验：成功提示、支付记录状态是否变「退款处理中」、会员状态是否仍显示（属正常）、实际金额与去向。

## 金额与尾差

实测：申请 ¥869.00，实到 ¥867.10，尾差 ¥1.90。

**必须如实标注尾差**，不要四舍五入抹掉。用户发现数字对不上会怀疑整个流程。
