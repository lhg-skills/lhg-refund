# 自动化路线图（谁能做，谁不值得做）

> 结论先给：**12 个平台里，只有 3 个值得做自动化。**
> 剩下 9 个没有自助退款入口——不是技术问题，是**根本没有可点的按钮**。做了也是白做。

## 为什么大多数平台不值得自动化

自动化的前提是"有一条稳定的、可重复的点击路径"。现实是：

| 类型 | 有没有自助入口 | 自动化价值 |
|---|---|---|
| 工具类 SaaS（扣子、WPS） | 有网页端入口 | **高** |
| 商店代收（Apple） | 有网页表单 | **高**（但流程短，做好引导即可） |
| 内容社区（星球、知乎） | App 内入口 / 只有客服 | 低—中 |
| 视频音频网盘（腾讯、爱奇艺、网盘、喜马拉雅） | **没有**，只能找客服 | **零** |
| 课程（得到、小鹅通） | **没有**，找机构 | **零** |

对后两类，用户卡住的不是"点不到按钮"，是"**不知道该找谁、该说什么、什么时候截止**"。

所以产品重心应该是：**决策 + 模板 + 时效提醒**，而不是"替用户点击"。

---

## 评分模型

六个维度，各 1–5 分，加权后排序。标「估算」的是主观判断，不是实测数据。

| 维度 | 权重 | 说明 |
|---|---|---|
| 有可自动化的入口 | ×3 | 没有入口直接 0 分，一票否决 |
| 退款政策松紧 | ×2 | 越松越值得做（做成了用户真的能拿到钱） |
| 客单价 | ×2 | 金额越大，用户越需要，口碑越好 |
| 用户规模 | ×1.5 | 估算 |
| 入口稳定性 | ×2 | 会不会三天两头改版 |
| 合规/风控风险 | ×2 | 越容易被判 AI 越扣分 |

> 「一票否决」的意思是：没有自助入口的平台，不管其他维度多高，**不进自动化队列**。

## 排序结果

### Tier 1：现在就该做

| 平台 | 入口 | 分数 | 理由 |
|---|---|---|---|
| **扣子 Coze** | 网页端，四层路径 | **已完成** | 唯一"按剩余价值退"的平台，路径已实测，金额大（¥869 级） |
| **Apple（reportaproblem）** | 网页表单 | 42/50 | 用户量最大、金额大、流程短（选原因→选项目→提交）。难点是登录必须用户自己做 |
| **WPS** | 网页工单 + "买错会员" | 34/50 | 有明文"买错"通道，等于官方承认误购可退，成功率高 |

### Tier 2：做"半自动"，不做全自动

| 平台 | 为什么降级 |
|---|---|
| **知识星球** | 入口在 App 内，网页端没有。且**72 小时硬窗口**——真正有价值的是"到期提醒"，不是自动点击 |
| **知乎盐选** | 无自助入口，只能在线客服。自动化的价值只剩"帮你把话术发出去" |

### Tier 3：不做自动化，只做模板

腾讯视频、爱奇艺、百度网盘、喜马拉雅、剪映、得到、小鹅通 —— **没有可点的退款按钮**。

这些平台的正确产品形态：

```
用户描述情况 → 判断路径 → 给一段能直接发的话 → 告诉他 48 小时没回复就升级
```

**不需要浏览器。** 需要的是话术准确、渠道顺序对、时效提醒到位。

## Tier 1 的三个平台，各自怎么做

### 扣子（已完成）

- 模式：全自动（ego-lite），走到确认弹窗前停
- 关键：从首页进，不直达 `subscription/manage`
- 状态：`实测`

### Apple reportaproblem

**难点不在点按钮，在登录。** Apple ID 登录必然触发双重认证（验证码发到用户设备），agent 不能碰。

所以正确形态是**半自动**：

```
agent 打开 reportaproblem → 导航到"请求退款" → 把屏幕交给用户登录
→ 用户登录后，agent 继续选项目、选原因、填说明 → 停 → 用户点提交
```

**不要试图做全自动**：双重认证这一步绕不过去，硬做只会触发风控。

价值点：帮用户**选对原因**。选错原因（"不符合预期"）通过率明显低于"未收到项目"——但这个必须真实。

### WPS

- 入口：`helpdesk.wps.cn` / WPS 客户服务中心小程序「买错会员」
- 形态：半自动（网页工单，agent 填表，用户提交）
- 关键：**把"反悔"翻译成"买错"**——这是话术价值，不是自动化价值

## 自动化的技术前提（ego-lite 已满足）

| 需求 | ego-lite 能力 |
|---|---|
| 用用户自己的登录态 | 持久 profile |
| 登录交给用户 | `task.handOff()` |
| 拟人输入 | `keyboard.type()` 逐字 |
| 拟人指针 | `mouse.move/click/wheel` |
| 不被 CDP 探测 | Page 会话默认隐藏 console |

具体规范见 `human-ops.md`。

## 排期建议

```
第 1 批（已完成）：扣子 —— 验证"自动化 + 拟人化"这条路走得通
第 2 批：Apple reportaproblem —— 用户量最大，半自动，验证 handOff 流程
第 3 批：WPS —— 验证"误购话术 + 网页工单"
────────────────────────────────────
其余平台：只做模板，不做自动化
```

**为什么这个顺序**：先用扣子证明技术可行，再用 Apple 证明"登录交还用户"这套流程能规模化，最后用 WPS 证明"话术本身就是价值"。

三批做完，产品的三种形态（全自动 / 半自动 / 纯模板）就都有了样板。

## 一个反直觉的判断

**自动化的边际价值，远低于话术的边际价值。**

同一个平台，用户自己点进去、说错第一句话，照样被拒；说对话术，哪怕是自己手动点的，也能退。

所以优先级应该是：

```
判断对不对（决策框架）  >  说什么（话术）  >  谁去点（自动化）
```

这也解释了为什么你上一版 skill 明明能跑通，用户还是退不掉——**能点 ≠ 会退**。
